# W3 虚构资料与固定问题集

这些是本项目自行编写的虚构评测资料，不对应真实企业或真实人物，可供开发和公开测试。

- `documents.json`：11 份资料，包含办公制度、项目资料、产品手册三类；仅 `text` 和 `title` 进入材料库，版本、归属等元数据留作实验清单。
- `expectations.json`：36 题及原文依据，标签不入库。每类 10 题，另有 6 道范围/冲突/注入/错误题。`evidence_groups` 的每一组是一项必要依据，组内标识为可替代依据；全部组召回才算必要依据齐全。
- 每题含问题、人工关键词、范围、依据、必要事实、条件/禁止推断、可答性和来源授权。问题中的“当前/新版”以语料标注时的版本为准，不跟系统日期自动漂移。
- `dev` 共 25 题，`holdout` 共 11 题。留出题仅在冻结基线及最终选型/调优结束后运行；日常实验默认只跑 dev。首次基准已测所有题，留出题属于“未用于调参”，不能宣称“从未看过”。若以后用留出题调参，应补充新的独立验证题并记录版本。

在仓库根目录运行：

```powershell
.venv/Scripts/python.exe tests/eval/w3_rag_baseline.py -n 3
.venv/Scripts/python.exe tests/eval/w3_rag_baseline.py --split all -n 3
```

输出到 `.tmp/eval-runs/w3-baseline-<悉尼时间>/`，包括原始查询与命中、切片快照、生命周期检查、分组统计及输入哈希/依赖版本。文件夹每次新建，不覆盖。正式数据库和 `.env` 均不修改；全部查询使用脚本临时数据库，结束后释放引擎并清理。

`raw_question` 把自然语言原问题直接交给现有 search 函数；`manual_keywords` 使用标签中预先写好的关键词。后者不是模型选词表现，也不是自然语言端到端能力。当前显式范围由脚本把资料标识转为材料 ID，未实现知识库归属或有效版本过滤，不能据此验收 W3-03。

计分比较“命中的完整块包含预期原文”和“工具摘要包含预期原文”，分别报告必要依据覆盖率。无答案题的 Recall 为 null，不把没有依据的题计为100%。检索到无答案相关文档也不自动算幻觉；生成、拒答和引用支持须在后续问答评测中验证。

当前每份短文约一块，跨片段题以多个来源块构成；这是工程起点，尚不覆盖长文档、PDF/Word 解析、跨页表格或大库排序压力。PDF/docx 真实入库样例在 W3-04 扩充，不能把本基准的 add_text 当作文件批量解析验证。异常检查仅覆盖空 TXT、损坏 docx 和损坏或不支持的旧 doc 输入，未验证所有文件异常。

W3-02 用同一题集、范围和依据对比本地向量与混合召回：原问题分别交给检索器，人工关键词结果单独展示。需要输出同样的来源/版本/块引用，召回后的依据覆盖不能替代事实归属判定。若切片变化，应将固定原文依据重新映射到新切片，不能照抄旧块号。

## 可公开复现的本地 Embedding 检查

安装项目可选依赖后，手动下载公开模型；两个准备脚本只请求模型与配置，不读取业务资料。BGE为中文默认候选，Jina为中英双语候选；Jina文件约643MB，按需准备。

```powershell
pip install -e ".[dev,rag]"
python tests/eval/w3_prepare_models.py
python tests/eval/w3_prepare_jina.py
python tests/eval/w3_bilingual_smoke.py
```

模型文件仅保存在`.tmp/w3-models/`，不提交Git。编码入口是`briefly.llm.create_local_embeddings(model_dir)`，只读已准备的本地模型并核对文件哈希，不自动联网下载。冒烟检查同时需要两个模型，结果写`.tmp/w3-bilingual-smoke.json`；它只验证纯英文、中英混排、中文能正常编码，不代表跨语言召回或答案质量已验收。

Jina制品的分词器默认预算为512token；显式使用更长预算时通过`max_input_tokens`传入，适配器会同步实际运行分词器。更换模型、维度或预算后应使用新的索引身份。正式知识库入库、自动召回和问答集成仍在后续开发阶段。
